# 风车谷：Unity 三人小队 ARPG 章节

日期：2026-10-14。用户已将目标从双遭遇原型提升为一个章节规模的箱庭探索，谜题采用轻量环境解谜：机关、推箱、路线解锁。本轮直接扩展现有 Unity 工程。

## 体验目标

保留《马里奥与疯兔：王国之战》式的圆润块面、明亮配色、厚草皮、夸张植物和可辨认地标。操作采用《伊苏7》方向的三人小队即时战斗：控制一人、两人跟随协战、随时切人、普攻／技能／闪避。探索、解谜与战斗位于同一连续场景。

章节的内容规模由 **8 个有主题和高差的箱庭、6 场遭遇（23 名敌人）、7 组谜题、8 道条件关口、5 个补给宝箱和一条回环捷径** 构成。每段主要路径都连接一个新的空间目标或交互；机关会改变真正可通行的路线，风车高地提供章节中段的地标与路线重组。

场景与角色继续使用原创程序化占位资产；当前目标是完成可玩的章节布局和机制闭环。完整商业级美术、正式角色动画、音效、装备成长、复杂技能树与多人联机不在本轮交付范围。章节体验时长与帧率须由本轮实测确定，不能用地图面积或旧版本试玩时间推断。

## 工程与技术

项目根目录为 `prototypes/toy-garden-unity`，场景为 `Assets/_Game/Scenes/ToyGarden.unity`。在 Unity Hub 中添加这个项目文件夹，使用 **Unity 6000.6.5f1** 打开。包版本为 URP 17.6.0、Input System 1.19.0、AI Navigation 2.0.12、Cinemachine 6.6.0；实际版本以包清单和锁文件为准。

场景尺度为 1 Unity unit＝1 m，Y 轴向上。角色由 CharacterController 执行移动、重力、闪避和击退；队友采用 `NavMesh.CalculatePath` 查路，然后由同一个控制器行进。锁门的碰撞与动态导航阻挡随状态一起切换，避免只更新任务文字却仍能穿越关口。

当前输入通过代码创建 `InputActionMap`，镜头采用高机位跟随，探索与战斗间改变距离。正式动画与技能数据化仍待制作，已有程序动作和伤害窗口用于验证玩法。

## 章节空间

主路为 **入口村落 → 苹果果园 → 水渠工坊 → 钟表庭院 → 风车高地 → 古树林 → 山脊遗迹 → 守护者山顶**。风车机关开启后，风车高地与苹果果园之间增加可双向使用的捷径。

| 区域 | 中心坐标 X/Y/Z（m） | 平台尺寸（m） | 主要内容 |
| --- | --- | --- | --- |
| A 入口村落 | `(0, 0, 0)` | 48 × 40 | 出生、拉杆教学、通往果园的第一关口 |
| B 苹果果园 | `(0, 0, 60)` | 48 × 44 | 遭遇 1、推箱压板、通往水渠的坡道 |
| C 水渠工坊 | `(64, 2, 60)` | 44 × 44 | 遭遇 2、三个刻度转盘 |
| D 钟表庭院 | `(64, 5, 124)` | 44 × 44 | 遭遇 3、绕开另一种石块布局的推箱 |
| E 风车高地 | `(0, 5, 124)` | 48 × 44 | 风车拉杆，同时开放主路与回环捷径 |
| F 古树林 | `(-64, 5, 124)` | 44 × 44 | 遭遇 4、三个顺序开关 |
| G 山脊遗迹 | `(-64, 8, 60)` | 44 × 44 | 遭遇 5、两个刻度转盘 |
| H 守护者山顶 | `(-64, 8, 0)` | 44 × 40 | 遭遇 6、最终守护者与护卫、章节出口 |

桥与坡道约 8 m 宽，供三人队伍连续行走。角色出生点为 `(-12, 0.05, -12)`，出口位于 `(-64, 8, -12)` 附近。上述坐标是当前生成器的章节布局约定，后续调整时须同步更新导航与实走测试。

每个箱庭内部保留战斗空地与机关的操作空间；树木、建筑与高装饰集中在外围，避免遮挡角色、敌人预警和可互动对象。平台边缘通过草皮、土层、围栏和装饰建立厚实的小型场景观感。章节扩展通过主题变化、路线折返和高差形成层次，不以重复空路代替可玩内容。

## 解谜与关口条件

| 谜题 | 位置 | 操作与正确状态 | 开放条件 |
| --- | --- | --- | --- |
| P0 拉杆 | A | 靠近拉杆按 E | 开放 A → B |
| P1 推箱压板 | B | 箱子由 `(1,1)` 到 `(3,3)`；先北两格再东两格 | P1 完成且遭遇 1 清除，开放 B → C |
| P2 三转盘 | C | 从左至右刻度 `1、2、3` | P2 完成且遭遇 2 清除，开放 C → D |
| P3 推箱压板 | D | 箱子由 `(1,1)` 到 `(3,3)`；先东两格再北两格 | P3 完成且遭遇 3 清除，开放 D → E |
| P4 风车拉杆 | E | 靠近拉杆按 E | 同时开放 E → F 与 E ↔ B 捷径 |
| P5 顺序开关 | F | 依次按标记 `1 → 3 → 2`，代码索引 `[0,2,1]` | P5 完成且遭遇 4 清除，开放 F → G |
| P6 双转盘 | G | 从左至右刻度 `2、1` | P6 完成且遭遇 5 清除，开放 G → H |

推箱采用 5 × 5 离散棋盘，每格 2 m。玩家站在箱子一侧按 E，箱子朝远离玩家的一侧前进一格；越界、石块占用或站位不合法时不移动。未完成的推箱谜题提供重置机关，防止错误移动造成永久卡关。完成状态锁定，重复交互不会重复发放完成进度。

转盘每次交互前进一档；场景提示给出目标组合。顺序开关按错会重置序列，让玩家可以立即重试。机关可在战斗中操作，但关口仍要求对应战斗清除，因此不能仅靠解谜绕过遭遇。暂停、失败或胜利时拒绝游戏交互。

遇到机关时 HUD 显示当前操作提示；区域标题和章节进度帮助玩家判断位置和下一步目标。宝箱属于可选补给，每个宝箱只奖励一次。通关要求 **全部 7 组谜题与 6 场遭遇完成**，随后在山顶出口按 E。

## 系统分工

| 组件 | 职责 |
| --- | --- |
| `GardenGame` | 输入、小队控制、遭遇激活／清除、暂停、失败、胜利与重试；向章节系统转交交互与目标 |
| `GardenChapter` | 章节区域、遭遇入口条件、机关选择、关口更新、解谜与补给计数、出口判定 |
| `GardenPuzzle` | 拉杆、推箱、转盘和顺序谜题的状态机、合法性检查及复位 |
| `GardenMechanism` | 场景中的交互位置、交互范围、类型、谜题与索引归属 |
| `GardenGate` | 根据谜题和遭遇状态同步更新门的可见性、物理碰撞与导航阻挡 |
| `GardenActor` | 三名英雄与敌人的数值、位移、跟随、协战、攻击、技能、闪避、生命与死亡 |
| `GardenProjectile` | 弹体运动、障碍碰撞、伤害与命中去重 |
| `GardenCameraRig` / `GardenHUD` | 跟随镜头、区域导览、队伍状态、解谜和目标反馈 |
| `GardenSceneBuilder` | 生成可编辑章节地形、桥坡、装饰、角色、谜题、关口与保存导航资源 |
| `GardenPlayModeTests` | 输入、战斗、真实位移、谜题、门锁约束、章节闭环与重置验证 |

角色和技能参数仍在 `GardenActor` 的角色类型分支内；运行中的生命与冷却保存在实例上。切换操控角色保持这些状态，并只允许一名队员接收玩家输入。死亡时自动接管存活队员，全队死亡进入失败；重试重新创建一次完整章节的初始状态。

## 操作与制作流程

| 动作 | 键鼠 | 手柄位置（Xbox 示例） |
| --- | --- | --- |
| 移动 | WASD | 左摇杆 |
| 普攻 | 鼠标左键 / J | A |
| 闪避 | Space | B |
| 技能 | Q | X |
| 切人 | Tab | LB |
| 机关／推箱／宝箱／出口 | E | Y |
| 章节地图／关闭地图 | M | RB |
| 暂停／继续；地图中关闭地图 | Esc | Start |
| 失败或完成后重试 | R | Select / View |

按 M 打开章节地图时暂停游戏，按 M 或 Esc 关闭后恢复；R 只在失败或完成界面重开，普通暂停状态不会重开。点击底部队员卡片也可切人。游戏失去焦点时暂停，回来后按 Esc 或点击 RESUME。输入以当前相机的水平朝向计算，保留摇杆幅度并限制对角线速度。

在编辑器中使用 **Toy Garden → Open Prototype Scene** 打开场景。需要重建默认章节时，退出 Play Mode 后使用 **Toy Garden → Rebuild Prototype Scene**；该操作会覆盖默认场景，手工调整前应另存场景。生成器同时保存材质、网格、Prefab 与导航数据。

**Toy Garden → Build macOS Prototype** 将应用输出到工程中的 `Builds/ToyGarden.app`。源码保留 `Assets` 与 `.meta`、`Packages`、项目设置和说明；`Library`、`Temp`、日志、用户设置、构建结果和测试产物保持忽略。
