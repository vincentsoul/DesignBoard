# Unity 玩具花园箱庭：三人小队 ARPG 原型

日期：2026-10-14。状态：Unity 原型工程、C# 代码与生成场景已完成，6 项 Play Mode 自动测试全部通过；macOS 独立应用完成键盘主线通关与重试验收。手柄实机、宝箱支路实机体验和性能仍未测试。

## 已确认方向与交付范围

- 引擎采用 Unity，首版为单机三人小队 ARPG。
- 视觉参考《马里奥与疯兔：王国之战》：紧凑箱庭、圆润块面、明快色彩、厚草皮、层叠地形，以及容易辨认的风车地标。
- 使用 WASD／左摇杆连续自由移动，操控一人、两名 AI 跟随协战，并可实时切人。
- 借鉴《伊苏7》的队伍结构，先用近战剑士、重击手、远程射手建立操作差异；不制作掩体、网格移动、行动点或回合制。
- 本轮已从设计方案进入原型工程制作。当前交付包含项目配置、运行时代码、场景生成器与 Play Mode 测试源码；正式角色动画、完整命中素材和技能数据化留在下一阶段。

《伊苏7》官方资料可用于了解三人编队与实时切换的参考方向。本工程的场景比例、角色数值和战斗规则是独立原型设计，不是原作数据。[Falcom：Party Play](https://www.falcom.co.jp/ys7_psp/system/system_01.html)

## 第一关：风车果园

**5–8 分钟是后续内容与节奏调整目标，当前尚未达到或验证。** 本次 macOS 键盘功能验收的主线路径耗时 1 分 19 秒，包含普通战、坡道、精英战与出口交互，未领取宝箱。当前关卡用圆角几何体、简单材质、树木灌木、石路、围栏和风车建立可辨认的玩具花园。

主线为 **入口 → 花园广场普通战 → 坡道 → 上层风车精英战 → 出口**；宝箱支路从下层区域分出。探索与战斗使用同一个场景，遭遇激活后镜头拉远，清敌后恢复探索距离。

| 区域 | 当前内容 | 体验目的 |
| --- | --- | --- |
| 入口 | Blade、Hammer、Ranger 三人出生点 | 熟悉移动、跟随、切人 |
| 花园广场 | 3 名 Grunt 近战敌人＋1 名 Spitter 远程敌人 | 学习普攻、攻击预警和闪避 |
| 奖励支路 | 可交互补给箱 | 鼓励探索，给存活队员恢复生命，每次流程只领取一次 |
| 坡道 | 连接下层与约 +3 m 上层区域 | 验证队伍连续行走与高差导航 |
| 风车战斗区 | 1 名 Boss 精英敌人 | 综合验证小队协战、技能和走位 |
| 出口 | 两场遭遇完成后开放的出口交互 | 完成反馈与重试入口 |

场景生成器负责实际坐标和地形尺寸；当前两处遭遇中心分别为 `(-10, 0, -5)` 与 `(20, 3.04, 19)`，宝箱为 `(-24, 0, 9)`，出口为 `(0, 3.08, 24)`。上层战斗地面为 3.04 m，出口平台为 3.08 m，以小台阶连接层次。这些坐标是本轮白盒布局参数，可在验证后调整。

空间调整遵循以下规则：

1. 广场中央保留连续空地，树丛、围栏与箱子集中在外缘，给闪避和追击留空间。
2. 坡道、桥头和通路接缝先保证 CharacterController 与导航网格能顺畅通过，再增加装饰。
3. 减少战斗地面的高频花纹与持续粒子，让敌人预警圈和角色轮廓清晰。
4. 高建筑尽量放在镜头远侧；当前优先通过摆放处理遮挡，遮挡淡出尚未实现。
5. 不以额外空路凑流程时长。先记录两场战斗与探索的实际耗时，再调整敌人数值和路线。

### 输入与操作

`GardenGame` 在代码中创建 `Gameplay` 的 `InputActionMap`，目前没有独立的 `GameInput.inputactions` 资产。输入集中转交当前队员，关闭时释放动作映射；暂停或结束时阻止继续执行游戏动作。

| 动作 | 键鼠 | 手柄位置（Xbox 名称示例） |
| --- | --- | --- |
| 自由移动 | WASD | 左摇杆 |
| 普通攻击 | 鼠标左键／J | 下侧面键（A） |
| 闪避 | Space | 右侧面键（B） |
| 技能 | Q | 左侧面键（X） |
| 切换队员 | Tab | 左肩键（LB） |
| 交互 | E | 上侧面键（Y） |
| 暂停／继续 | Esc | Start |
| 失败或完成后重试 | R | Select／View |

移动方向由相机 Forward／Right 投影到 XZ 平面后计算，保留摇杆幅度，并限制对角线输入长度。角色实例保存生命、技能冷却和动作状态；切人改变控制来源，保留原位置及这些状态。死亡队员不可接管，操控角色死亡后选择存活队员，全队死亡后进入重试状态。

屏幕底部队员卡片也支持点击切人，卡片点击不会同时触发普通攻击。游戏窗口失焦时自动暂停，回来后按 Esc 或点击 RESUME 继续。

### 镜头与移动

当前镜头固定高机位，俯角约 52°，垂直 FOV 48°；探索距离 18 m，战斗距离 25 m。`GardenCameraRig` 平滑共享目标，`CinemachineFollow` 负责跟随偏移。数值来自当前代码，尚未视为最终手感。

`GardenActor` 统一执行角色水平移动、重力、闪避与击退。导航使用 `NavMesh.CalculatePath` 查路径，再由 CharacterController 实际移动；没有同时让 NavMeshAgent 自动写入角色位置。友方身体碰撞不互相阻挡，跟随队员使用错开的目标位置，战斗中选择附近敌人，脱离战斗范围后回到队长附近。

地图静态碰撞由 `NavMeshSurface` 烘焙：地形与具有阻挡碰撞的环境物件（如树干、灌木）参与收集，纯视觉装饰与角色排除。生成器检查主要目标点的导航连通；实际上下坡与跟随稳定性另外由 Play Mode 测试检查。

### 战斗与角色差异

| 角色 | 当前普通攻击 | 当前技能方向 |
| --- | --- | --- |
| Blade | 较快近战攻击 | 扩大范围的近战范围伤害 |
| Hammer | 较慢、伤害较高的近战攻击 | 更大范围的重击 |
| Ranger | 远程弹体 | 三发扇形弹体 |

当前命中采用代码时间驱动的范围判定或弹体碰撞；近战每次攻击只结算一次，弹体维护命中规则。敌人攻击带前摇和预警圈，角色有闪避无敌窗口、冷却、受击与死亡逻辑。攻击轨迹、武器摆动、受击闪色等为程序化占位反馈。

弹体与预警／攻击效果分别使用 `Materials/Projectile.mat` 和 `Materials/Effect.mat`，通过 `GardenGame` 的序列化引用随场景构建。环境与角色材质使用统一调色板；生成器在 Linear 色彩空间下将调色板颜色转换后写入材质。

目前没有正式 Animator 动画片段与 Animation Events，也没有已完成的三段连击、完整技能树或武器相性系统。后续接入动画时，应让动画事件驱动命中时机，并保留受击／死亡／重试时清理动作状态的逻辑。角色和技能参数当前在 `GardenActor` 的角色分支内；将它们提取为 ScriptableObject 是下一阶段任务，运行中的生命和冷却仍应保留在各自实例。

## 场景生成与继续搭建

现有工程可以直接继续制作，无需另建空项目：

1. 用 Unity 6000.6.5f1 打开 `prototypes/toy-garden-unity`，等待包解析和编译。
2. 打开 `Assets/_Game/Scenes/ToyGarden.unity`。需要重新生成时，退出 Play Mode，运行 **Toy Garden → Rebuild Prototype Scene**。
3. `GardenSceneBuilder` 会重建默认场景并保存 `Materials`、`Meshes`、`Prefabs` 与 `Scenes/ToyGardenNavMesh.asset`。有手工布局修改时，先另存场景，避免被重建覆盖。
4. 在 Game 窗口验证移动、切人、战斗、交互与重试；修改脚本数值后重新运行，记录手感变化。
5. 在 Test Runner 中运行 PlayMode 的 `GardenPlayModeTests`。自动测试通过后，继续检查真实键鼠／手柄和镜头视觉。
6. 下一轮建立约 10 × 10 m 完整美术样板，确认草皮、石路、树木与风车的造型比例后逐步替换整关。
7. 将确认过的角色与技能常量数据化，接入正式动画、声音、粒子和更完整的敌人行为。

本机构建使用 **Toy Garden → Build macOS Prototype** 菜单，默认输出到项目内的 `Builds/ToyGarden.app`，构建成功后可从 Finder 打开。该菜单由 `GardenBuild` 实现，构建与实际运行结果分别记录在下方验收中。

源码提交包含 `Assets` 及 `.meta`、`Packages` 与 `ProjectSettings`。`Library`、`Temp`、`Logs`、`UserSettings`、构建产物、测试输出和个人 IDE 设置由项目 `.gitignore` 排除。独立应用属于本地验证产物，不加入源码提交。
