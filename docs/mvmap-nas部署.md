# MVMap NAS 后端与同步

MVMap 已接入 DesignBoard 的 Node 服务和 Docker 镜像。NAS 运行一套服务即可同时提供白板和地图，复用原有 HTTPS、账号、会话和跨站写入保护，无需单独的数据库或新端口。

## 飞牛 OS 部署

在现有 DesignBoard 仓库目录执行：

```sh
git pull --ff-only
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
```

保留已有 `.env`、`secure/`、`compose.override.yaml` 和数据卷。已有 HTTPS 部署应继续使用安全覆盖配置，不能退回不带认证的公网服务。

入口是原有域名端口下的 `/mvmap/`；例如现有服务地址是 `https://evantra.cloud:4173/`，地图入口就是 `https://evantra.cloud:4173/mvmap/`。先在首页登录，然后点击“打开 MVMap 地图编辑器”。访问地图时未登录会返回首页。

如果是新 NAS，可沿用仓库 README 中的 Docker 和 HTTPS 部署步骤。局域网直接访问的默认端口为 4173；默认基础 Compose 没有开启登录，仅适合可信局域网。只运行一个应用实例访问同一数据目录；不要让多容器共同写同一目录。

## 保存位置与备份

容器内：`/data/boards/mvmap/<地图ID>.json`。它位于现有持久化数据卷内，重建容器仍保留；不会作为普通白板出现在白板列表中，也不会提交 Git。

删除地图会移动到 `/data/boards/mvmap/.trash/`，文件名带唯一后缀。恢复时将回收站 JSON 导入编辑器即可；不必直接修改服务器文件。回收站暂不自动清理。

如果希望在飞牛文件管理器直接管理数据，可以按仓库 README 将现有数据卷迁移到 NAS 文件夹挂载。**先备份并复制旧数据，再修改挂载；直接换成空目录会导致已有文件暂时不可见。** 保证容器的 UID/GID 1000 可以写入。飞牛定时备份应覆盖整个 `boards` 数据目录；删除 Docker 数据卷会删除地图。

## 多设备使用

1. 所有设备打开同一个 NAS 地址并登录。
2. 在地图编辑器中创建或导入地图。修改后约 600 毫秒自动保存到 NAS，同时在当前浏览器保留本地备份。
3. 另一台设备打开“地图库”读取最新地图。已经打开同一地图时，点击“刷新 NAS”读取服务器版本。
4. 本版本是文件同步，不是实时协同光标，也不自动合并同时编辑的内容。
5. 同一版本的地图同时保存时，只允许一个成功。另一端显示版本冲突，不覆盖 NAS 文件。点击“另存副本”保留自己的版本，或先导出 JSON，再刷新 NAS。
6. 断网或登录过期时显示未同步提示。恢复网络/在首页重新登录后，点击“重试保存”。没有确认成功前不要关闭页面。
7. “本地备份”可查看本机浏览器保留的地图，恢复时创建新 ID，防止覆盖 NAS。清理浏览器数据仍会删除这些本地备份。

离线文件模式和 `python3 -m http.server` 模式仍使用本地存储；只有通过 Node 服务的 `/mvmap/` 入口打开才启用 NAS 同步。原来 8088 端口上的本地地图需要导出 JSON，再在 NAS 版导入；不同来源不共享浏览器数据库。

## API

全部路由受现有登录配置保护；请求体上限 30 MiB。地图格式保留原版 version 1。每次读取返回内容哈希 `revision`。

| 请求 | 用途 |
|---|---|
| GET `/api/mvmaps` | 返回 `{maps:[{doc,revision}]}` |
| GET `/api/mvmaps/:id` | 读取 `{doc,revision}` |
| PUT `/api/mvmaps/:id` | 提交 `{doc,baseRevision}`，首次创建使用 null |
| DELETE `/api/mvmaps/:id` | `If-Match` 请求头传当前 revision，删除至回收站 |

版本不匹配返回 409；登录过期返回 401；无效数据返回 400；跨站写入返回 403。服务端按地图串行执行版本检查及写入，临时文件写完后原子替换，避免半写入文件。文件哈希也能检测外部修改。外部程序不要在服务运行时直接覆盖文件，原子写入也不是多进程文件锁。

## 本地开发与验证

```sh
node server.mjs
# 打开 http://127.0.0.1:4173/mvmap/
node tests/mvmap.test.mjs
node tests/mvmap-sync.test.mjs
```

测试覆盖持久化重新读取、并发写冲突、过期版本删除、回收站、格式验证、跨站写入、登录保护，以及客户端刷新列表后仍保留编辑基准版本、冲突备份和重试队列。部署后应再用实际 NAS 地址检查登录、保存、另一设备读取和容器重启恢复。
