# 边境之旅本地复现版产品设计文档

PDD 1.0 · 2026 年 10 月 16 日

产品对象：Android 客户端 4.2.0 的本地复现版及配套服务端。读者：产品、客户端、服务端、交互、内容与测试人员。文档用于确定产品体验、功能规则、开发范围和验收口径。

产品目标是让玩家在原有旅行场景中完成采集、整理、制作、交易与安家的连续体验，并让所有资产变化能够保存和恢复。首个可玩版本优先完成“同一角色重新登录 → 场景与背包加载 → 完成一次旅行和制作 → 退出后继续”，随后扩展营地交易、小镇和长期成长。

当前已完成原 APK 的重打包与本地服务器登录链路；角色出生、场景加载和背包交互尚未通过运行验收。服务端已有独立业务原型，但其功能不能直接等同于原客户端内可用功能。本文将产品目标与这一实现基线分别列出。

## 阅读导航

第 1 至 4 章定义依据、现状、目标与范围；第 5 至 15 章描述玩家旅程、核心系统和页面；第 16 至 20 章规定数值、数据、服务边界、质量与指标；第 21 至 24 章给出开发阶段、验收、待验证问题和来源。文中的功能编号可直接用于拆分研发任务。

### 1 2 适用版本

基线 APK 为 `com.netease.ma71`，版本 4.2.0，versionCode 420；本地变体使用独立包名 `com.netease.ma71.local`。客户端包含 Unity 2018.4.35f1、IL2CPP、xLua 和 Wwise 资源结构。[E01][E04]

既有公开资料复刻方案用于体验参考。[E11] 本文以该 APK 的证据和当前本地实现为开发基准，不把国际版、旧国服、新世界或 PC 版的规则合并为一个确定版本。客户端保留的旧接口、测试内容和未启用配置应单独记录。

### 1 3 本版统一决策

- 初期沿用修改后的原客户端及本地 HTTP 适配路径；原 MOS2/NEX 字节协议兼容不作为首个可玩版本的前置条件。
- 小镇原型容量继续采用当前实现的 8 人；该值是演示参数。未来容量应配置化，不采用早期方案中的 20 人作为已确认原作规则。
- 首个可玩版本只开放一种可消费的普通货币。客户端中的其他货币字段维持明确的兼容值，不建立未经验证的兑换和支付流程。
- 将旅行体力、精力与其他疲劳字段分开建模；现有 `energy` 演示字段不直接映射所有原字段。
- 原 APK 内资源用于本地适配验证。公开版本的素材来源与发行范围另行确定；仓库不包含 APK、提取资源和签名材料。

## 2 当前产品与实现基线

### 2 1 已完成范围

| 层级 | 已确认内容 | 尚不能据此确认 |
| --- | --- | --- |
| 资源与结构 | 已提取原始文件和可转换资源；恢复 857 个 Lua TextAsset | 完整 Unity 工程、场景绑定和所有资源可用 |
| 原客户端登录 | 修改版 APK 实际发送登录、角色列表、进入游戏及设备消息 | 角色已出生、地图可玩、库存可操作 |
| 原客户端响应 | 原 Lua 回调处理 364、358、360 三类响应 | 所有后续业务回调兼容 |
| 独立业务服务 | 8 个模块、17 个变更命令，SQLite 持久化 | 这些命令已经接入原客户端界面 |
| 自动化检查 | 上一实现轮次 37 项测试通过 | 37 项完整游戏功能已完成 |
| 运行设备 | Android 11 API 30 ARM64 模拟器 | 用户手机及其他 Android 版本适配 |

登录验证首次成功于 2026 年 10 月 15 日 12:01，北京时间；最终构建复核于同日 12:07。APK 为 ARM64 测试包，约 700.4 MiB，通过 v1、v2、v3 签名检查。[E04][E05]

### 2 2 当前实际链路

修改版 APK 启动 → 载入原 Lua 与登录界面 → 本地游客认证 → 返回角色列表 → 发送进入游戏 → 原回调开始场景加载。

请求通过 USB 调试端口转发访问 Mac 上的 `127.0.0.1:4317`。客户端发送已解码的命令和字段，服务器通过 `/api/client/message` 返回消息；这是一条新增 HTTP 适配路径。[E04][E06]

当前停在进入游戏后的资源加载阶段，并出现原 SDK 网络错误提示。隔离测试阻断了测试包的外部网络请求，但 APK 内仍有 SDK 初始化和网络尝试。该状态属于“登录链路通过”，不是“可玩版本”。

### 2 3 必须解决的缺口

1. 登录桥每次认证会创建新游客；固定展示的角色编号不能证明再次打开会找回同一存档。需要稳定的本地身份与会话恢复。
2. 角色初始化需要嵌套属性、外观、旅行状态与多个系统的初始数据；仅回复进入成功无法满足场景启动。
3. 原客户端库存以物品 UID、容器和位置组织；服务端演示库存按类型计数，需要新增实例模型与转换层。
4. 原 SDK 残留、资源加载依赖和错误弹窗需要逐项定位，未适配入口不能继续触发远程等待。
5. 采集、任务、装备和营地 UI 尚未与服务端形成完整的运行闭环。

## 3 产品定位与成功标准

### 3 1 产品定义

本产品是一款以徒步旅行为主线的轻生存与经营游戏。玩家在有限的携带能力下收集资源，在营地把资源加工成补给、装备和交易品，再把旅行收益投入小屋与小镇。每次旅行都应产生明确的用途和积累。

旅行提供探索感，背包提供取舍，制作提供能力成长，营地提供短期结算，家园提供长期目标。产品质量首先取决于这些环节能否相互驱动，而不是开放的系统数量。

### 3 2 目标玩家与场景

以下为待试玩验证的用户假设，不是用户研究统计。

| 玩家需求 | 典型场景 | 产品回应 |
| --- | --- | --- |
| 短时间放松与看景 | 5 至 15 分钟完成一段旅行 | 清晰的营地目标，可安全退出 |
| 收集与整理 | 挑选材料、整理有限空间 | 物品用途、重量与摆放反馈清楚 |
| 制作与持续成长 | 为新装备安排两三次旅行 | 配方需求可追踪，进步可见 |
| 经营与轻社交 | 装饰小屋、为小镇贡献 | 个人资产清晰，合作无需强制在线 |

首期不以竞技对抗、战斗刷装或开放世界自由移动作为核心卖点。路线上的陪伴角色若为 NPC，应明确其身份。

### 3 3 产品成功的三个层次

**可连接**：原客户端与本地服务完成认证和必要消息交换。该层已局部达成。

**可持续游玩**：玩家完成旅行、背包、制作与存档闭环；重新打开后继续同一角色；失败和断线不会复制或吞掉资产。该层是下一版本的核心目标。

**有长期目标**：路线、配方、装备与家园相互提供需求，多次旅行产生不同取舍；交易和小镇能够稳定结算。该层在基础闭环通过后验证。

## 4 产品范围与优先级

| 优先级 | 功能范围 | 本阶段交付判断 |
| --- | --- | --- |
| P0 基础可玩 | 本地身份、场景、角色、背包、单段旅行、采集、食物、制作、存档恢复 | 原 APK 内完成一次闭环并重启恢复 |
| P1 核心体验 | 多路线、装备与配方成长、任务、营地交易、私人仓储与基础小屋 | 连续三次旅行有不同目标且经济可解释 |
| P2 合作经营 | 双客户端交易、小镇成员、公告、贡献、共享仓储与公共建设 | 并发操作无重复物品和重复入账 |
| P3 扩展内容 | 宠物、职业、景观、跑商、活动和收藏 | 各模块独立验收后开放 |

首期不接入原游戏账号、充值、广告、真实支付、公开匹配和跨设备云账号。基础看景、免费恢复和存档不依赖这些系统。已有界面中未支持的功能隐藏入口或明确显示“当前版本暂未开放”，不可返回伪成功。

最低内容目标为 1 个起点、1 条完整路段、1 个营地、3 类可采集资源、2 个可用配方、1 种可食用物和 1 个仓储入口。数量是交付目标；实际资源编号必须先验证，不因名称相近就直接映射。

## 5 核心循环与玩家旅程

### 5 1 三层循环

短循环：发现资源 → 判断用途 → 拾取或放弃 → 整理背包 → 处理体力 → 继续前进。

中循环：营地准备 → 徒步采集 → 到达营地 → 制作与补给 → 出售或储存 → 更新下一目标。

长循环：完成任务 → 解锁配方和路线 → 获得更好旅行能力 → 建造家园与贡献小镇 → 产生新材料需求。

### 5 2 新玩家首次进入

首次启动完成本地身份创建与数据加载后，玩家应看到可操作角色和一个明确目的地。基础装备和少量安全补给随角色初始化一次发放，不因重连再次赠送。

教学顺序为行走与暂停、拾取、背包整理、到达营地、制作、使用食物、保存退出。前两次教学操作不引入不可恢复损失；跳过教学后保留说明入口和必要物资。

| 目标时段 | 玩家行为 | 结束条件 |
| --- | --- | --- |
| 首次 0 至 3 分钟 | 看懂目的地，拾取一种材料 | 第一件物品进入真实库存 |
| 3 至 8 分钟 | 整理背包并到达营地 | 营地状态已保存 |
| 8 至 15 分钟 | 制作并使用或保留产物 | 材料、产物和体力变化一致 |
| 再次进入 | 继续同一角色 | 位置、库存与成长恢复 |

这些时段是体验目标，需在实际场景可玩后测量，不作为当前已达成绩。

### 5 3 老玩家再次进入

身份校验成功后恢复上次确认状态。存在未确认操作时先核对回执，再展示最终库存。营地中恢复为休息状态；路途中恢复到保存点并短暂暂停，让玩家看清体力、负重和下一目标后再继续。

失去会话不能自动创建一个看似相同的新角色。应提供“恢复本地角色”或明确的新建入口。新建会产生独立存档，不覆盖旧角色。

## 6 登录与角色初始化

**依据与现状。** 登录 258、角色列表 263、进入游戏 260 的请求及相应回调已运行确认。`net_avatar.lua` 的初始化逻辑读取 `prop`，随后调用库存全量与掉落查询。[E04][E06][E07] 角色初始化本身尚未运行通过。

### 6 1 功能要求

**AUTH-01 本地身份。** 首次启动生成稳定本地身份标识并安全保存；同一安装的重启和会话续期对应同一服务器角色。服务器维护身份、角色与会话的关联。清空应用数据后的恢复能力必须明确，不承诺当前不存在的云备份。

**AUTH-02 会话恢复。** 未过期会话可继续使用；到期时恢复角色并签发新会话。认证失败不静默清空存档。测试多角色时显式选择角色，界面不可仅凭固定 ID 判断当前人物。

**ROLE-01 角色载入。** 返回角色名称、有效外观、地点、旅行状态、资产、背包和必要功能状态。暂未开放模块以客户端可接受的关闭状态初始化，不用随机值填补。角色、场景和库存均达到就绪状态后才开放主操作。

**ROLE-02 命名与外观。** 首期使用一个已验证的默认外观，可修改角色名。后续再开放完整外观编辑。名称失败时保留输入并解释原因；外观资源缺失时回退到已验证默认资源，不进入无限加载。

### 6 2 状态与异常

启动 → 检查本地身份 → 认证 → 选择或恢复角色 → 加载角色与场景 → 库存同步 → 可操作。

任一步失败都应停在对应状态，提供重试与返回。网络超时后仍有未确认请求时不能再次发放初始资源。客户端只有收到当前连接的有效响应才推进状态，旧连接的迟到响应不得覆盖新会话。

### 6 3 验收

同一角色连续重启 3 次，角色内部 ID、名称和库存不变；模拟会话过期后仍找回原角色；首次加载失败后重试只发放一次初始资源。角色实际出现并可操作，不能以“进入游戏响应成功”代替这一验收。

## 7 徒步路线与资源采集

**依据与现状。** 客户端存在旅行信息更新、生成物品、体力恢复、倒地掉包及旅行重连处理；配置包含营地与路段关联。[E08] 这些属于静态确认。当前服务端只接受演示营地坐标保存，不包含有效旅行模拟。

### 7 1 行走与地图

**WALK-01 路线前进。** 玩家沿已验证路径移动，支持暂停和调整行进速度。保留原客户端可用交互；新增控制应提供点按替代，避免背包拖拽同时触发行走手势。暂停、全屏设置和切后台时，P0 暂停旅行消耗。

**MAP-01 路线选择。** 地图以营地与路段组成连接关系，展示目的地、解锁条件和主要资源。未验证资源不得开放为可进入路线。已到达营地允许重走对应路线，不能通过任意提交营地坐标跳过解锁。

**WALK-02 旅行状态。** 每次出发建立旅行实例，保存路线、资源生成种子、进度、采集记录和体力。到达终点后先确认结算，再播放到达反馈。重复到达消息只结算一次。

### 7 2 资源交互

**RES-01 唯一采集。** 每个可采集资源具有实例 ID、类型、位置和领取状态。服务器校验资源属于本次旅行、未被领取且玩家有资格获得；客户端不能直接请求任意物品数量。

**RES-02 放入背包。** 拾取先预览，合法放入后提交。空间不足或操作取消时，资源保持可领取或进入明确的临时托盘；不得同时存在于地面和库存，也不得无反馈消失。

**RES-03 资源可达。** 教学材料固定保底，普通资源按路线配置生成。错过主线材料可重走或通过已开放补给渠道获取。工具与材料解锁不得形成循环依赖。

P0 只启用散落物采集。伐木、狩猎、钓鱼等交互分别确认资源、工具和请求后纳入后续版本，不能仅依据资源文件名宣布可玩。

### 7 3 验收

完成一条路线后只有一次奖励；在采集提交前后分别退出，重进均不复制资源；点击已领取资源不能再次增加库存；未开放营地和不存在的路线返回可理解的错误。

## 8 背包物品与仓储

**依据与现状。** `inventory_pto.lua` 包含物品 UID、打捆、装备、容器摘要、容器详情、跨容器移动和食物使用描述。[E09] 当前服务端只有 `backpack` 与 `storage` 的数量表，没有原客户端物理布局、独立耐久和装备实例。

### 8 1 物品模型

**INV-01 实例与定义分离。** 物品定义保存用途、外形、重量、堆叠规则、价格和资源引用；物品实例保存 UID、归属、容器、数量、位置、品质或耐久。服务端生成 UID，客户端不可用同一 UID 声明多个所有者。

**INV-02 容器类型。** 首期开放背包与私人仓储；交易托管、装备位、临时领取托盘使用独立逻辑容器。共享仓库在权限和日志完成后开放。容器类型与原数字 ID 的对应关系必须由适配清单管理。

### 8 2 摆放与空间

**INV-03 拖拽。** 开始拖拽时建立临时预览，目标合法后提交一次归属或位置变化。取消、触控中断与失去焦点时撤销预览。布局坐标与资产归属分开保存，动画不能创建或删除物品。

**INV-04 容量。** 空间与重量分别展示。空间约束决定能否摆放，重量影响旅行成本。首期以可验证的布局判定为准，不依赖完全自由物理的偶然结果。背包溢出先提示和回退，不静默毁损物品。

**INV-05 整理与拆合。** 同定义、同状态且允许合并的物品才能合并；拆分创建新的合法 UID，数量总和不变。快捷整理先预览，无法容纳时不自动丢弃。原客户端的“打捆”结构需要单独适配，不能直接等同数量相加。

### 8 3 使用与转移

**INV-06 物品详情。** 展示名称、用途、数量、价值、重量及适用的耐久和保留标记。任务相关物品突出用途；出售或丢弃已保留物品时明确确认。

**INV-07 仓储转移。** 从来源扣除与向目标加入必须在一次事务中完成。目标已满、权限不足、数量变化或物品被交易锁定时，不修改任何一侧。普通背包整理不触发额外资源奖励。

**INV-08 丢弃与领取。** 主动丢弃与永久删除使用不同动作。地面丢弃保留可领取状态和过期规则；永久删除必须告知结果。当前 `inventory.drop` 实际删除数量，不能直接冒充可捡回的掉落功能。

### 8 4 验收

采集、合并、拆分、仓储转移和交易后，实例 UID 不重复、数量守恒；移动中断不出现两份物品；重启后布局合法、归属不变；库存摘要与详情能够一致地驱动原背包界面。

## 9 旅行体力精力与装备

**依据与现状。** 旅行模块具有 stamina 更新与恢复；`EnergyMgr` 另维护当前精力、上限和恢复时序，`energy_effect` 配置包含三档状态及效果字段。[E08][E12] 因此应按不同资源处理。原型 `energy` 初值 50、上限 100，只用于演示食物恢复。

### 9 1 旅行体力

**STA-01 消耗。** 体力随实际旅行消耗，受距离、速度、负重、地形和装备影响。公式与参数版本化，服务器校验合理变化；客户端展示预测值和服务器确认值。P0 在参数未完整恢复前采用明确的测试配置。

**STA-02 食物。** 使用前展示恢复量，确认后扣除具体物品并恢复体力。满体力时不默认消耗；批量使用需显示有效恢复与溢出量。当前服务端允许满值时继续扣物，这属于需修正差异。

**STA-03 倒地与救援。** 体力耗尽停止行走，显示可用食物与免费返回营地选项。P0 不损失物品。若后续启用掉包，必须同时实现所有权、保护时间、回收入口和损失清单，不能只播放倒地动画。

### 9 2 精力与其他状态

**ENE-01 独立状态。** 精力与旅行体力在字段、图标、来源和消耗说明上分开。P0 不让精力成为基础旅行门槛；需要兼容的界面返回固定关闭状态或已验证默认值。后续恢复精力增长与消耗时使用服务器时间。

`toil`、饱腹及其他状态保留独立待验证项，不因翻译相近而合并。原配置中的阈值只能作为静态值；生效场景、边界比较与服务端修正需进一步确认。

### 9 3 装备

**EQU-01 装备位。** 首期验证鞋、衣物、背包和工具中实际可用的部位。每个装备实例独立管理，装备与背包归属互斥；替换时展示属性差异。

**EQU-02 耐久与损坏。** 耐久按有效使用计量，不按离线时间扣除。P1 默认损坏后停止加成并保留物品；修理与销毁必须区分。更换小背包导致容量不足时阻止替换或先整理，不能丢失已有物资。

### 9 4 验收

暂停不扣旅行体力；使用一个食物仅扣一次并恢复正确数值；更换装备前后增益可解释；服务器重启后耐久不回满；体力为零时始终有可完成的恢复路径。

## 10 制作配方任务与成长

**依据与现状。** 配方协议包含熟练度查询、配方升级与级别、经验字段。服务端已实现按演示配方制作，但原制作提交路径尚未完整映射。[E03][E10]

### 10 1 制作

**CRA-01 配方展示。** 展示输入材料、拥有量、输出、用途和解锁条件。缺失材料可跳转到已开放来源说明。默认只展示当前阶段相关配方，锁定配方保留明确的获取目标。

**CRA-02 制作事务。** 确认时校验配方已解锁、材料属于玩家且未被锁定、输出有去处；随后原子扣料并生成物品。失败时材料不减少。重试同一操作返回同一结果，不重复产出。

**CRA-03 输出接收。** 背包不足时阻止制作并说明原因，或将产物放入持久化领取托盘；同一版本必须统一规则。P0 采用阻止并保留材料，P1 可新增托盘后再调整。

**CRA-04 熟练度。** 只由成功制作或明确配置的行为增长；升级消耗与收益可预览。客户端已有熟练度结构并不证明所有配方都采用同一增长算法。

### 10 2 任务

**QUE-01 任务类型。** 首期采用教学、采集、制作、到达四类；后续加入交易、装备和家园需求。主界面展示一个主目标，其他目标进入任务页，避免同时遮挡旅行视野。

**QUE-02 计数。** 累计采集按成功领取事件计数；提交任务在确认时扣物；首次到达只触发一次；制作以成功事务计数。存档加载、物品转入转出和重复响应不能重复推进。

**QUE-03 领奖。** 达成条件与领取奖励分开保存。奖励有唯一领取记录，满包处理与制作规则一致。任务失败或资源错过时给出可达的补救路线。

### 10 3 成长节奏

P0 用两个配方验证“材料变成有用物品”；P1 建立“新配方 → 新装备 → 新路线 → 家园需求”的成长关系。首 30 分钟建议至少出现一次明显装备或携带能力提升，时长由试玩修订。

不得用重复新建游客带来的初始奖励支撑真实进度；测试发放入口与正常成长分开。已知配方、熟练度、任务进度和领取状态必须属于稳定角色存档。

### 10 4 验收

材料不足和输出受限时不扣料；同一制作请求重复发送只产生一份产物；任务材料位于可达区域；奖励重试和重新登录都不再次发放。

## 11 营地交易与经济交换

**依据与现状。** 客户端交易描述包含初始化、上架、购买、位置与价格更新、结束及售卖上限；营地配置存在机器人货币、背包与购买时序字段。[E08][E10] 这支持营地交易和机器人行为的结构存在，不足以证明所有路人身份或实际成交算法。

当前服务端实现固定价格托管市场，支持上架、整单购买和取消。它没有营地传送带、倒计时、自动回收和 NPC 买家。[E02][E03]

### 11 1 营地流程

**CAM-01 到达。** 到达营地后展示恢复、制作、交易、仓储和下一路线入口。先完成旅行结算，再启用经济操作；结算失败时允许重试，不直接跳到下一路线。

**TRD-01 上架。** 玩家选择物品与数量，查看预计价格，确认后物品移入托管。上架物不能再被制作、装备或消耗。取消时返回同一资产，不新建一份同物品。

**TRD-02 购买。** 服务端确认商品仍开放、价格有效、余额和接收空间足够后，一次性完成扣款、入账和归属转移。买方不得提交最终余额，身份来自当前会话而非请求中的任意玩家 ID。

**TRD-03 展示与结算。** P1 可先采用原界面可支持的固定价成交。传送带位移与动态价格仅在对应消息和配置确认后启用。成交价以服务器确认时的有效规则为准，价格变化必须在确认前可见。

**TRD-04 未售出物品。** 首版交易结束自动返还未售出物，不默认折价销毁。后续若加入 NPC 回收，必须明示价格、触发点和取消时机。NPC 成交和玩家成交分开记录。

### 11 2 异常与恢复

两个买家争抢时只有一单成功；失败方不扣钱。卖家离线不影响已经提交的成交；重新进入后同步回执。超时状态显示“正在确认交易结果”，不得立即返还已成交商品。

经济回滚只由事务结果决定。界面取消动画、进程退出或网络中断都不能直接撤销已经提交的交易。

### 11 3 验收

双角色完成上架、购买和取消；钱币与物品转移可核对；并发购买无超卖；卖家离线后仍获得一次正确收入；原客户端至少完成一次真实成交后才标记 APK 交易完成。

## 12 家园小镇与合作经营

**依据与现状。** 客户端符号及配置覆盖地块、建镇、规则、公告、资金、贡献与多种公共建筑。建筑配置同时存在启用、未启用和占位项，不能把列表全部当作开放功能。[E03][E13]

当前服务端支持 8 人演示小镇、成员、镇长编辑、货币贡献和排行；未实现家具场景、房屋升级或共享仓库。现实现离镇删除成员贡献记录、解散不返镇资金；这些不是已确认原作规则。

### 12 1 私人家园

**HOM-01 家园入口。** P1 让玩家获得一个可稳定进入的私人空间和仓储。进入、退出与路线存档关联，不能把家园加载失败当成角色丢失。

**HOM-02 建设与布置。** 升级前展示材料、货币、外观与容量收益。家具在持有、摆放和回收间转换时保持同一资产身份；非法位置不能提交。访客默认不能拿走私人物品。

### 12 2 成员与治理

**TWN-01 建立与加入。** 每角色只属于一个镇，容量由配置决定。建镇或搬迁有费用时先展示并由服务端结算。P0、P1 不将入镇作为旅行门槛；单人仍可完成基本成长。

**TWN-02 权限。** 镇长可修改镇名、规则和公告；普通成员可查看、贡献并参与已开放公共功能。所有修改在服务端验证成员身份和版本。界面隐藏按钮不能替代权限校验。

**TWN-03 离镇与解散。** 离镇保留个人资产；公共捐赠不自动退还。贡献流水持久保存，当前成员排行可移除离镇者。镇长转让和解散分别设计，解散前清晰展示影响。当前原型的直接删除行为需在 P2 前迁移为可追溯记录。

### 12 3 公共资金与仓库

**TWN-04 贡献。** 个人货币扣除、镇资金增加与贡献记录一次完成；不能因刷新或物品反复转入转出重复计分。贡献比例为配置项，当前 1:1 只是演示规则。

**TWN-05 共享仓库。** 只接收显式捐赠物。展示领取权限、额度和记录；多人领取同一物品只有一人成功。个人暂存与公共捐赠应使用不同入口和文案。

**TWN-06 公共建设。** 每个建设项目包含目标、已投入量、参与记录与完成状态。投入和完成奖励分别幂等结算；取消、迁出与服务器重启不得产生双重返还。

### 12 4 验收

双客户端的镇容量和地块不冲突；普通成员无法修改镇长字段；贡献总额能与资金流水核对；搬家后个人物资完整，不能带走共享库存；公共建设只完成和领奖一次。

扩展范围根据客户端静态结构及既有产品研究列入规划，均未完成原 APK 运行验收。每个模块开放前必须具有有效数据、可退出界面、资产一致性和存档恢复能力。

| 模块 | 已有依据 | 目标功能与开放条件 |

| 宠物 | 跟随、喂养、技能、探索、背包等接口 [E14] | 先跟随互动，再增加辅助采集；先明确宠物物品与玩家物品归属 |

## 14 内容组织与视听体验

### 14 1 内容使用原则

原 APK 资源导出包括贴图、精灵、网格、文本和音频，但导出对象数包含重复，不能作为独立道具或关卡数量。[E15] 应以“可在运行场景使用的资源组合”为交付单位。

**CNT-01 资源登记。** 每个启用内容必须记录逻辑 ID、资源引用、依赖、展示名称、来源和运行验证状态。无效引用在构建检查阶段发现；占位内容不能混入正常随机池。

**CNT-02 内容阶梯。** P0 只使用一组已验证角色、营地、路线和物品。P1 扩展目标为 2 至 3 个营地、3 条可重复路线、6 至 12 个配方及一个小屋；数量可因实际资源与触控表现调整。

### 14 2 视觉与声音

保持旅行风景和角色可辨认，资源交互范围不能覆盖主要视野。小物品扩大点击命中区域；选中、可拾取、已锁定与满包状态除颜色外还应有形状或文字提示。

优先恢复拾取、放入背包、制作、食用、成交和到达的短反馈，再恢复环境声和背景音乐。音频 ID 与文件导出之间需要事件映射验证，文件可播放不代表游戏事件调度正确。

低体力警告应清楚但不过度打断；网络与资产异常使用文字解释，避免只给红色图标。关闭音乐不应关闭必要操作提示，声音和振动可独立设置。

## 15 页面结构与交互规范

### 15 1 信息架构

启动与恢复 → 角色加载 → 旅行主界面 → 营地。

旅行主界面通往背包详情、地图、任务与暂停设置；营地通往制作、交易、仓储和下一路线；家园与小镇在对应阶段增加入口。P0 不要求所有系统同时显示。

| 页面 | 主要动作 | 必须展示的状态 |
| --- | --- | --- |
| 本地登录 | 继续角色或显式新建 | 连接进度、失败原因、存档身份 |
| 场景加载 | 等待或重试 | 当前阶段、重试入口，不假报百分比 |
| 旅行 | 行走、采集、进食 | 目的地、距离、体力、负重 |
| 背包 | 查看、摆放、使用、转移 | 所有权、数量、空间、锁定原因 |
| 地图 | 选择可达路线 | 解锁条件、主要资源、补给建议 |
| 营地 | 恢复、制作、交易、出发 | 旅行结算状态、下一目标 |
| 制作 | 选择与确认配方 | 材料缺口、输出、解锁条件 |
| 交易 | 上架、购买、取消 | 价格、数量、归属、确认状态 |
| 家园与小镇 | 储存、建设、贡献 | 私有或共享、权限、费用 |
| 设置 | 声音、操作、存档与退出 | 当前角色、未确认操作、恢复说明 |

### 15 2 通用交互

**UX-01 触控。** 主要操作建议至少 44×44 逻辑点；实际在手机上检查。拖拽从背包开始后锁定用途，不能触发行走加速。点按替代应能完成关键拾取与使用功能。

**UX-02 操作状态。** 统一区分未提交、提交中、已成功、已失败、结果待确认。提交中禁止再次发起同一动作；结果待确认允许查询，不直接展示失败并返还。

**UX-03 错误文案。** 玩家文案说明受影响动作与恢复方式；命令号、堆栈和内部字段写入诊断日志，不出现在常规流程。测试版可保留独立诊断入口。

### 15 3 错误反馈样例

| 场景 | 玩家提示 | 可执行恢复 |
| --- | --- | --- |
| 服务未启动 | 暂时无法连接本地服务器 | 重试连接、查看连接说明 |
| 背包放不下 | 背包空间不足，物品尚未领取 | 整理或取消 |
| 制作材料变化 | 材料数量已变化，请重新确认 | 刷新配方与库存 |
| 交易响应超时 | 正在确认交易结果 | 查询状态，避免再次购买 |
| 场景资源缺失 | 当前地点暂时无法载入 | 返回已验证营地或退出 |
| 功能未开放 | 当前版本暂未开放此功能 | 返回上一页 |

| 浆果效果 | 每个恢复 5 | 满值仍会扣物，需按需求修正 |
| 商品买价 | 木材 2、纤维 2、浆果 3、木板 8、绳索 8、口粮 10 | 没有 NPC 售出价体系 |
| 堆叠上限 | 单类型每容器 9999 | 属于技术演示上限，不是背包容量 |
| 小镇容量 | 8 | 配置化后再调整 |
| 贡献比例 | 货币与贡献 1:1 | 演示规则 |
| 每周奖励 | 货币 25、浆果 2 | 当前每个角色均可领，没有小镇资格限制 |

当前市场把货币从买家转给卖家，不凭成交产生额外货币。商店购买和镇资金贡献是个人货币流出；新游客与每周奖励是流入。新的稳定身份必须先完成，才能评估长期经济。

### 16 2 产品经济规则

**ECO-01 来源与消耗。** 每种资源至少有明确来源和用途。旅行产出支持食物、装备、出售与家园；普通货币用于补缺材料、修理和建设。路线不因一次错误消费永久无法继续。

**ECO-02 定价。** 配方成本、购买价、NPC 回收价和奖励分别配置。防止“商店买料 → 制作 → 系统售出”产生无条件无限利润。若允许专业制作获利，需通过时间、限量或资源投入表达成本。

**ECO-03 控制范围。** 价格、配方、体力变化、奖励和权益在服务端校验。客户端仅提交行为意图，不能直接提交最终余额或任意新增物品。

**ECO-04 调参与观察。** 记录三次完整旅行的采集量、食物消耗、制作量、卖出收入和补给支出。首先消除生存死锁，再调整收益节奏。未形成可玩闭环前不以留存或付费预测判断数值成功。

### 16 3 旅行公式草案

P1 测试可采用“距离 × 基础消耗 × 速度修正 × 负重修正 × 地形修正 × 装备修正”。所有系数属于测试配置；暂停时不产生距离增量。速度已经影响行程时间，额外速度修正只表达单位距离成本，避免重复计入速度。

每次出发展示预计消耗与可用补给。教学路段在合理拾取情况下无需额外付费即可到达；装备收益应能在同一路线对比中感知。

## 17 数据对象与存档要求

### 17 1 目标数据模型

下表为产品所需的逻辑对象，字段名不是对原服务器结构的完整恢复。

| 对象 | 最小字段集合 | 生命周期要求 |
| --- | --- | --- |
| 本地身份与会话 | identityId、playerId、有效期、状态 | 身份稳定，会话可更新 |
| 角色 | playerId、名称、外观、revision | 重新登录恢复同一实体 |
| 物品定义 | definitionId、类别、资源、重量、效果 | 配置版本可追溯 |
| 物品实例 | uid、definitionId、数量、归属、状态 | UID 唯一，数量不可为负 |
| 容器 | containerId、类型、owner、容量、布局 | 资产转移原子完成 |
| 旅行 | journeyId、routeId、种子、进度、采集记录 | 断线可恢复，不重复产出 |
| 生存状态 | stamina、energy、各自上限与时间 | 两类数值不可混用 |
| 配方与任务 | 解锁、熟练度、进度、领取状态 | 行为计数与领奖去重 |
| 交易单 | listingId、物品、买卖方、价格、状态 | 状态单向推进并保留回执 |
| 小镇 | townId、成员、权限、资金、revision | 容量与权限由服务端裁定 |
| 操作回执 | operationId、请求摘要、结果、版本 | 重试返回原结果 |

### 17 2 保存与恢复

**SAVE-01 保存点。** 采集、使用、制作、交易、任务领取、仓储转移和营地到达确认后持久化；客户端保存必要显示状态和身份。未确认操作保存为待核对，不伪装成成功。

**SAVE-02 版本与幂等。** 状态变更携带操作 ID 和预期版本。相同操作重复发送返回原结果；旧版本冲突要求刷新后重新确认。新状态不可被迟到旧响应覆盖。

**SAVE-03 迁移。** 从类型计数库存迁移到物品实例时，生成一次性迁移记录，核对总量，保留可恢复备份。失败后恢复旧数据，不创建半套 UID。无效资源引用隔离并报告，不能删除玩家全部存档。

### 17 3 在线边界

本地服务器是当前玩法资产的权威，离开服务无法提交新资产变化。P0 在断线时暂停经济操作并显示重连；不承诺离线旅行结算。若后续开放离线看景，应与可交易物品和共享资产明确隔离，并另行设计冲突合并。

## 18 客户端与服务端职责

### 18 1 系统关系

原 Unity 场景与 UI → Lua 网络适配 → 本地 HTTP 消息桥 → 角色与业务服务 → SQLite。

客户端负责输入、动画、资源显示与操作预览；服务端负责身份、资产归属、业务规则、权限、版本和事务。适配层负责把原客户端字段转换为本地模型，并把业务结果组装成客户端实际需要的响应。

### 18 2 已验证协议映射

| 请求编号 | 用途 | 响应编号 | 状态 |
| --- | --- | --- | --- |
| 258 | 本地游客认证 | 364 | 原客户端运行确认 |
| 263 | 角色列表 | 358 | 原客户端运行确认 |
| 260 | 进入游戏请求 | 360 | 原客户端回调确认，场景未就绪 |
| 1001 | 设备信息消息 | 空消息列表 | 收到请求，未保存设备载荷 |
| 1020 | 心跳 | 893 | 桥接已实现，当前适配未启用定时心跳 |

接口描述与客户端回调优先于枚举名称推断。现有旧传输 RSA、RC4 和角色 protobuf 实验保留为独立研究，不计入这条 HTTP 路径的兼容完成度。[E04][E06]

### 18 3 需要补齐的适配

**API-01 初始化。** 按 `S_AVATAR_INIT` 的实际读取链建立必需字段清单，逐项映射角色、地点、外观、资产、配方及扩展关闭状态，再处理其触发的库存与掉落请求。

**API-02 库存。** 覆盖容器摘要、容器详情、跨容器移动、食物使用与装备。每类消息必须有字段来源、失败响应、状态刷新方式和真实 UI 验证记录。

**API-03 业务桥接。** 制作与交易不能仅返回状态码；需要同步所有受影响对象，包括卖方资产变化。尚不支持的命令返回明确错误并配合关闭入口。

**API-04 重连。** 请求队列有超时、取消和重试规则。旧会话请求不得混入新角色；有副作用的请求不能无操作 ID 自动重发。心跳完成后再定义掉线判定与恢复策略。

独立业务原型的 17 个变更命令包括角色命名与位置、物品移动/删除/使用、制作、购买、周期奖励、交易上架/购买/取消，以及建镇/入镇/更新/贡献/离镇/解散。具体接口见 E02；这些仍需逐项适配到原客户端。

## 19 质量性能与运行要求

以下为验收目标，不是当前测量结果。

| 类别 | 目标 | 验证方式 |
| --- | --- | --- |
| 冷启动 | 服务正常时 60 秒内进入可操作场景 | 连续 5 次，记录加载阶段和失败原因 |
| 操作响应 | 本地联机关键操作 P95 不超过 1 秒 | 至少 100 次采集、使用和制作事务 |
| 渲染表现 | 目标 ARM64 手机常规旅行稳定接近或达到 30 FPS | 固定路线 10 分钟，记录平均与卡顿 |
| 稳定性 | 连续 30 分钟核心循环无阻断崩溃 | 原客户端操作并保存日志 |
| 持久化 | 关键事务前后中断均无重复和丢失 | 至少 20 组故障注入场景 |
| 兼容性 | API 30 模拟器与至少一台实际手机通过 P0 | 记录系统、内存、ABI 与构建号 |
| 可诊断性 | 关键错误能定位到阶段和操作 | 关联请求 ID、阶段与错误码 |

当前仅验证 API 30 ARM64 模拟器，不能将 APK 声明的 minSdk 21 视为全部版本已适配。包体约 700.4 MiB，优化前先建立各类资源与启动耗时基线，避免为了减包误删场景依赖。

**OPS-01 本地启动。** 提供启动服务、健康检查、设备端口转发和启动 APK 的一套说明。检测服务不可达时给出可操作提示，不让用户反复点击无反馈按钮。

**OPS-02 日志。** 记录构建版本、会话内请求关联号、消息类别、处理结果和耗时；不记录账号凭据、会话 token、完整设备信息或原 SDK 登录载荷。测试数据与日志保持仓库忽略。

**OPS-03 外部依赖。** 对仍会发起外部请求的 SDK 建立清单；P0 不依赖其返回成功。优先移除阻断流程的初始化与弹窗触发点，并在隔离网络条件下验证。

## 20 产品指标与事件设计

### 20 1 指标定义

本阶段衡量体验闭环和数据正确性，不以小样本计算商业留存结论。

| 指标 | 计算口径 | 用途 |
| --- | --- | --- |
| 可操作到达率 | 成功进入可操作场景的启动次数 / 有效启动次数 | 区分认证成功与真正可玩 |
| 首次闭环完成率 | 完成采集、到达、制作并保存的角色数 / 开始教学角色数 | 检查引导和功能阻断 |
| 存档恢复成功率 | 状态核对通过的恢复次数 / 恢复尝试次数 | 发现新建游客和覆盖问题 |
| 资产异常数 | 重复 UID、负数数量、错误余额、重复奖励的记录数 | 必须为零的发布门槛 |
| 无效操作占比 | 因容量、权限或状态不明造成的失败操作 / 同类操作 | 识别 UI 提示问题 |
| 循环收益 | 每次旅行收入、消耗与净库存变化 | 调整制作、补给与交易 |

### 20 2 事件清单

建议事件包括 `app_start`、`auth_result`、`avatar_ready`、`scene_ready`、`inventory_ready`、`journey_start`、`resource_collect_result`、`item_use_result`、`craft_result`、`camp_arrive`、`trade_result`、`save_resume_result` 和 `town_contribution_result`。

通用字段为测试角色匿名标识、构建号、配置版本、会话内关联号、结果、错误码和耗时。以服务器事务结果记录资产事件，以客户端记录页面与交互事件，两者通过关联号核对，不重复统计一次操作。

指标不记录个人真实身份、聊天全文或 SDK 凭据。测试报告同时给出样本量、设备和构建版本；失败尝试不能从分母中删去以提高成功率。
