# 开发说明

## 当前架构

- `index.html` / `portal.css` / `src/portal.js`：登录主页、白板选择、搜索、新建和退出登录。
- `editor.html` / `styles.css`：白板编辑界面和样式，无构建步骤。
- `src/board.js`：界面状态、交互、渲染、撤销、画布切换和剪贴板事件。
- `src/model.js`：文档结构、元素创建、校验和几何计算。
- `src/clipboard.js` / `src/io.js`：元素复制粘贴、浏览器保存及 JSON/PNG 导入导出。
- `src/sync.js`：HTTP API 客户端、延迟保存、1.5 秒轮询远端修改。
- `server.mjs`：静态资源、画布 CRUD、健康检查；仅允许访问列出的前端资源。
- `src/board-store.mjs`：一画布一 JSON 文件、临时文件替换、内容版本号和删除回收站。
- `src/board-ops.mjs`：程序化元素操作及连接线更新，前端和 MCP 共用。
- `mcp-server.mjs`：stdio MCP，直接读取和修改数据文件。
- `tests/`：模型、剪贴板、文件存储、HTTP 和 MCP 测试。

## NAS 部署基线

Docker Compose 提供独立持久化卷、非 root 运行、只读应用目录、健康检查和自动重启。单实例运行；现有存储不是多人协作数据库。

公网部署增加 `compose.secure.yaml` 和 `deploy/Caddyfile`：Caddy 承担 HTTPS 和证书续期；`src/auth.mjs` 负责页面登录、scrypt 密码验证、随机会话令牌和错误登录限流，白板后端不再发布宿主机端口。NAS 上以 `compose.override.yaml` 自动启用，更新容器时继续保持访问保护。认证配置仅使用专用密码哈希，DNS 验证配置保存在 NAS 的受限目录，均不提交 Git。应用拒绝跨站 API 写入及非 JSON 保存请求。

图片内嵌在画布 JSON 中，HTTP 请求体上限为 30 MiB。画布变大后，轮询和整份保存会增加网络、内存和存储开销。

版本号检查可以拒绝顺序发生的过期写入；版本检查和文件写入之间没有跨进程锁，并发客户端或 MCP 同时写入仍可能产生竞态。冲突时客户端采用远端状态，并把原状态放入撤销记录。不能据此承诺实时多人协作。

## 建议后续顺序

1. 完成实际 NAS 部署验证：确认 CPU 架构、数据目录权限、重启后数据恢复以及反向代理下的剪贴板。
2. 外网基线已加入应用会话认证和请求来源校验；如需多个独立用户，再增加应用内账号、会话和画布权限。
3. 提升数据可靠性：自动备份、回收站恢复界面、写入并发控制和冲突提示。
4. 为大量截图拆分图片资源，减少整份 JSON 传输；改善大画布渲染和保存性能。
5. 根据实际需求加入画布搜索、标签、模板以及远程 MCP 接入。

功能开发继续保持零构建前端和模块职责；新增公开资源时同步更新 `server.mjs` 的资源白名单。涉及保存或协议的修改需要覆盖现有 HTTP / MCP 测试。

## 验证

```sh
npm test
docker compose up -d --build
docker compose ps
```

容器部署后创建带文字及图片的画布，重建容器后重新打开，确认内容保持；再验证 JSON 导入导出、删除回收站及 HTTPS 剪贴板。容器构建和 NAS 验证需要实际 Docker 环境。
