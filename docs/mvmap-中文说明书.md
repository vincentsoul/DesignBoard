# MVMap 中文功能调研与操作说明书

调研日期：2026-10-27。对象：[原站](https://titaniumcladstudios.github.io/MVMap/)、[官方源码与 README](https://github.com/TitaniumCladStudios/MVMap)。结论依据为当日线上 HTML、官方文档和源码；不是对所有浏览器兼容性的保证。当前中文版位于 `prototypes/mvmap-zh/`，保留 MIT 许可，来源版本记录见 `UPSTREAM.json`。

> 后续更新：已新增 NAS 后端。通过仓库 Node 服务的 `/mvmap/` 入口可使用自动保存和跨设备读取，见 [NAS 部署说明](mvmap-nas部署.md)。本文关于“仅浏览器存储”和“不支持同步”的描述针对原站及静态离线模式。

## 1. 这个网站能做什么

MVMap 是面向银河恶魔城（Metroidvania）游戏的二维地图规划工具。它把世界地图、房间内部布局、能力解锁关系放在同一个编辑器里，适合关卡策划在正式搭建引擎场景前设计探索路线、回访路径和能力门槛。

它是单文件 HTML 应用，不需要账户、安装依赖或联网服务。地图保存到当前浏览器，不会自动同步到其他设备，也不会写入 DesignBoard 的个人看板。

| 功能 | 具体能力 | 使用价值 |
|---|---|---|
| 世界网格 | 无固定边界、支持负坐标，每 8 格有粗线；平移、以鼠标位置缩放、适应画布、坐标显示 | 规划整体世界结构 |
| 房间 | 自由画笔、矩形填充、擦除；任意网格组合，可画 L 形、环形、竖井 | 房间无需局限为矩形 |
| 区域 | 新建、改名、配色、删除；房间按区域分组 | 区分生物群落、章节或关卡分区 |
| 房间属性 | 名称、所属区域、继承或覆盖区域颜色、设计笔记 | 记录敌人、秘密和设计意图 |
| 门 | 在格子边缘放置；通道、普通门、单向门；单向可反转方向 | 表达房间连接和回程限制 |
| 锁与钥匙 | 门分配锁，钥匙放在地图上；多对多关系；选中显示虚线关联，也可显示全部 | 表达能力解锁与探索节奏 |
| 提示 | 使用中的锁没有分配钥匙时显示警告 | 发现未配置的门槛 |
| 房间灰盒 | 4×、8×、16× 细分；九类方框；移动、缩放、标注；门作定位锚点 | 规划房间内部布局 |
| 地图库 | 多地图、本地自动保存、重新打开最近地图、删除 | 同一浏览器管理多个项目 |
| 文件交换 | 导入/导出 JSON，导出整张世界地图 PNG | 备份、交付和评审 |
| 撤销/重做 | 最多 120 个历史快照，覆盖灰盒修改 | 回退编辑操作 |

## 2. 启动中文版

直接打开 `prototypes/mvmap-zh/index.html` 即可使用。推荐在终端运行：

```sh
cd /Users/user/Documents/designboard/prototypes/mvmap-zh
python3 -m http.server 8088 --bind 127.0.0.1
```

然后访问 [本地中文版](http://127.0.0.1:8088/)。打开 [中文说明书](http://127.0.0.1:8088/manual.html) 可阅读和打印本说明。

此目录独立运行，不依赖仓库主应用的 `npm start`；主应用对静态文件设有白名单，默认不提供此原型的路由。端口被占用时可换端口，但不同端口属于不同浏览器存储来源。

直接以 `file://` 打开时，部分浏览器无法使用 IndexedDB，会回退到 localStorage。HTTP 方式通常更可靠。页面底部的回退提示提醒你及时备份；自动保存不能替代文件备份。

## 3. 界面位置

- 顶栏：地图名称、撤销/重做、地图库、新建、导入、导出、PNG、中文说明书、帮助、保存状态。
- 左栏：七种地图工具、区域、按区域分组的房间列表、关系线和房间名显示开关。
- 中间：地图画布；底部显示坐标、缩放比例和当前工具操作提示。
- 右栏：所选对象的属性、锁列表、钥匙列表。
- 灰盒视图：独立覆盖层；上方是方框工具、九类对象、网格细分和返回地图按钮。

## 4. 十分钟完成一张地图

1. 点击「新建」，在顶栏把地图改名为“废弃矿井”。原地图仍保留在地图库。
2. 在区域列表选择默认区域，双击区域名称改为“矿井入口”；点击色块切换配色。
3. 按 `B`，拖动画出入口房间。第一次绘制会自动创建房间，也可先点击房间列表的 `+`。选中房间，在属性中改名并写设计笔记。
4. 按住 `Shift` 使用画笔，画第二个房间“深层矿道”。房间之间留出清晰的公共边缘。按 `R` 可用矩形填充，按 `E` 擦除。
5. 按 `D`，点击两个格子之间的边缘放门。在右侧选普通门或单向门，并检查「连接」显示的两侧房间。
6. 按 `K`，在入口房间点击放钥匙，命名为“二段跳”。钥匙也可以表示物品或剧情条件。
7. 选中门，在「锁」下拉框选择「新建锁」，命名为“高台门槛”，勾选“二段跳”作为开启钥匙。
8. 打开「显示全部锁 ↔ 钥匙连线」，检查能力获取点与受限门的空间关系。
9. 按 `V` 后双击某个已绘制房间，进入灰盒。选平台类型并拖出平台，再用物品、敌人或注释布置房间。按 `V` 选择方框，可移动或拖动控制点调整大小。
10. 返回地图，按 `F` 适应画布。先「导出」JSON 备份，再点「PNG」生成评审图片。

## 5. 区域、房间与门

**区域**是颜色和分组容器。新增区域会同时创建一个房间，并切换绘制目标。切换区域时，原活动房间若属于其他区域，会退出当前绘制目标，下一笔在新区域创建房间。至少保留一个区域。

**房间**是网格集合，不要求连续。画笔把格子分配给活动房间；画到其他房间占用的格子会重新分配占用，擦除也会移除格子，请留意相邻房间。选择工具拖动房间时，其内部钥匙、灰盒及仅归它所有的门一起移动；与邻房共享的门保持原位。删除房间会删除其中的钥匙和灰盒，相关门也会随清理规则处理；建议先导出。

**门**位于格边，不位于格子中心。通道表示开放连接，普通门可分配锁，单向门可反转通行方向。属性会显示它实际连接的房间；出现“空白区域”说明该侧没有房间。按住 `Alt` 点击已有门可直接移除。

## 6. 正确理解锁与钥匙

“锁”是抽象门槛，例如“需要钩爪”，可以复用到多个门；“钥匙”是能力、物品或事件的地图标记。

**同一个锁勾选多把钥匙表示“任意一个满足即可”（OR），不是必须同时集齐（AND）。** 例如为“裂隙门槛”勾选钩爪和二段跳，表示二者任一可通行。一个钥匙也可开启多个锁。

选锁可勾选开启它的钥匙，选钥匙也可反向勾选它开启的锁。选中任一对象可看关联虚线；全量关系线适合评审，复杂地图可关闭以减少遮挡。

“未配置钥匙”警告只检查“已有门使用此锁，但它没有关联钥匙”。它不会模拟玩家移动、能力获取顺序、循环依赖或必经路线，不能证明地图可通关，也不会自动找出所有软锁。例如钥匙放在它自己开启的门后，仍需人工检查。

## 7. 灰盒布局

双击房间，或选中房间按 `Enter` 打开灰盒。细分表示每个世界网格边长被拆成 4、8 或 16 份。调整细分会缩放已有图形坐标，尽量保持世界位置。

| 数字键 | 类型 | 建议用途 |
|---|---|---|
| 1 | 实体 | 地面、墙壁 |
| 2 | 平台 | 跳跃落点 |
| 3 | 危险区 | 尖刺、伤害区域 |
| 4 | 水域 | 水体范围 |
| 5 | 梯子 | 攀爬路线 |
| 6 | 出口 | 房间出口占位 |
| 7 | 物品 | 奖励或道具 |
| 8 | 敌人 | 战斗布点 |
| 9 | 注释 | 设计标记 |

按 `B` 拖出矩形方框；按 `V` 选中，拖动移动或调整大小，在浮动属性中修改类型与标签；按 `E` 擦除。房间边界的门作为锚点显示。这里是设计示意，不会运行碰撞、敌人 AI、跳跃或水体物理。灰盒保存在 JSON 中；顶栏 PNG 导出的是世界地图，没有单独的灰盒图片导出按钮。

## 9. 保存、导入与导出

修改后约 600 毫秒触发保存，顶栏显示保存状态。IndexedDB 数据库名为 `mvmap`，对象仓库 `maps`；回退存储使用 `mvmap:docs`，最近地图记录在 `mvmap:last`。浏览器隐私模式、清理站点数据、改变域名/协议/端口都可能导致地图不可见或丢失。

- 「地图库」按更新时间排列地图，可以打开或永久删除；删除地图不是普通编辑撤销能恢复的操作。
- 「导出」生成包含区域、房间、门、锁、钥匙和灰盒的 JSON，可继续编辑，应作为正式备份。
- 「导入」读取 JSON 并分配新的地图 ID，因此不会直接覆盖地图库中已有地图。应导入受信任且来自 MVMap 的文件，原版只做基础字段补全，不是严格格式验证器。
- 「PNG」导出世界地图画面，用于评审；是否显示房间名称取决于显示开关。PNG 无法还原成可编辑工程，也不包含完整灰盒数据。
- 本地中文版和原站是不同来源，不能直接读取原站浏览器数据库。迁移步骤是：原站导出 JSON → 中文版导入 JSON。

中文版保持 `version: 1` 及全部字段、对象 ID、类型枚举不变，原有自定义名称、笔记、标签不会被自动翻译。新建对象默认名称为中文，中文地图名称也会保留在导出文件名中。

## 10. 适用范围与局限

适合早期世界结构、能力门槛、回访路线和房间布局讨论。它没有多人实时协作、账户和云同步、版本管理、游戏引擎直接导出、素材贴图、可玩测试或完整关卡可达性分析。没有专门的移动端布局；建议桌面浏览器和键盘鼠标。

单文件无第三方运行依赖，适合离线使用。官方说明以 Chromium 浏览器为主要测试对象；其他浏览器应先用小地图验证保存和导入导出流程。
