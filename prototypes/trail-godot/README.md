# 风途 · 营火之间

基于[现有 PDD](../../docs/trail-local-product-pdd-2026-10-16.md)制作的独立 Godot 3D 可玩 Demo。跟随小径旅行，收集松木、亚麻与野莓，在营火旁制作、交易、存放物资，再为更大的背包与河畔小屋出发。

2026-10-16 开发方向调整：以新的 Godot 客户端验证玩法。此工程使用原创程序化场景与本地存档，没有原 APK、提取素材或原客户端协议依赖。旧 PDD 中的 APK 适配、账号桥接与服务器阶段保留为历史背景；本次交付以本说明的范围为准。

## 运行

推荐 **Godot 4.7.2**，本次在 Apple Silicon Mac 上使用该版本验证。

1. 本机已导出应用：仓库根目录 `outputs/trail-godot/Windtrail.app`，双击运行，不需要启动服务器或 Godot 编辑器。
2. 使用源码运行：双击本目录 `Play.command`。默认使用 `/Applications/Godot.app`；也可用 Godot 打开 `project.godot`，按 F6/F5 运行主场景。
3. 命令行：`godot --path prototypes/trail-godot`，从仓库根目录执行。

导出应用为本机测试签名，包含 Apple Silicon 和 Intel 架构；实际运行验证在 Apple Silicon 上完成。当前未制作 Android 包，也未进行手机适配验收。

## 第一段旅程

1. 点击「选择路线 · 出发」，选择 **松风小径**。
2. 角色会沿路前进。点小径两侧的资源，或点左侧「拾取」；也可以按 **F** 拾取最近的一份。
3. 按 **Space** 停下看景，按 **1 / 2** 漫步或快走。体力不足时按 **E** 吃食物。
4. 走完 180 米自动进入营地，获得 18 叶币并恢复体力。打开「手作工坊」，用材料制作木板、麻绳和口粮。
5. 在「营地商人」卖出成品、买入补给；在「私人仓库」存取物品。打开「旅程手记」领取已完成目标的奖励。
6. 收集 **2 木板 + 3 麻绳 + 30 叶币** 升级背包；继续积累 **4 木板 + 2 麻绳 + 40 叶币** 建造小屋。走完首程后，260 米的暮色河谷开放。

两条路线共享基础地形，有不同长度、资源总量、到达奖励和日照氛围。按路线选择、停留和整理时间，一次核心循环约需 2–5 分钟；这是 Demo 的加速节奏。

| 操作 | 方法 |
| --- | --- |
| 采集 | 点击 3D 资源、左侧按钮或 F；有效距离为前后 14 米 |
| 停下 / 继续 | Space，或底部按钮 |
| 漫步 / 快走 | 1 / 2 |
| 恢复体力 | E，或点击食物查看恢复量后使用 |
| 物品详情 | 点击背包物品格 |
| 整理背包 | 拖动到另一已占用格交换位置，或点击「整理」 |
| 查看任务 | 「旅程手记」或 J |
| 关闭弹窗 | Esc 或「关闭」 |
| 提前结束旅行 | 「免费回营」；保留物品，恢复体力，不发放到达奖励 |

打开弹窗、切换到其他应用时自动暂停旅行。没有离线体力消耗。耗尽体力仍可吃食物或免费回营。

## PDD 对应与简化

| PDD 范围 | Demo 已实现 | 当前边界 |
| --- | --- | --- |
| WALK / MAP / RES | 两条引导路线、速度选择、独立旅行与资源实例、采集距离和防重复、到达结算 | 固定路线配置，没有自由移动、战斗、伐木和狩猎 |
| INV | 12 格 / 12 kg，升级后 16 格 / 18 kg；每格最多 5 件；物品详情、交换和整理 | 使用等尺寸物品格，无自由物理堆叠、旋转、拆分 UI 和地面丢弃 |
| STA | 距离、速度、负重影响体力；食物、满体力保护、免费救援 | 没有独立精力系统，也没有装备耐久 |
| CRA | 木板、麻绳、口粮三个配方；校验完整输入与输出容量后一次提交 | 无配方熟练度和等级树 |
| QUE | 采集、制作、到达、升级四个目标；手动领奖且只领一次 | 单人固定目标，无服务端日历或活动 |
| CAM / TRD | 营地休息、固定价格 NPC 即时买卖 | 明示 NPC，无玩家市场、托管、传送带或多人交易 |
| INV / HOM | 私人仓库、背包升级、可建造的 3D 小屋 | 仓库不限容量，小屋无室内和家具摆放 |
| SAVE | 单设备同一角色继续、旅行进度与已采集记录、原子文件替换、上次有效快照备份 | 本地 JSON 存档，无登录服务器、云存档与跨设备同步 |
| CNT / UX | 程序化松林、河流、山体、营地、角色行走动画、中文 UI、拾取反馈音 | 桌面鼠标键盘为本次验证目标，无 Android 触控验收 |

没有开放的 PDD 系统：多人小镇、共享建设、职业、宠物、活动、支付、原服务器接入。仓库现有 `trail-server` 未改动，本 Demo 不调用它。后续接服务端时应把本地规则迁移为服务器权威事务，并重新验证重复请求、并发与断线。

## 规则与存档

- 初始：25 叶币、100 体力、3 野莓、2 松木、3 亚麻。每次营地出发恢复满体力，不重复发初始物资。
- 采集：本次旅行的资源 ID 唯一；容量或重量不足时资源保持可领取。
- 制作、买卖、转移、升级和领奖：在副本中完成校验与变化，成功保存后才提交；写盘失败回退。
- 堆叠 UID 标识当前逻辑堆叠；拆合与跨容器数量转移可能生成新的堆叠 UID，不代表 PDD 的独立装备实例已经实现。
- 野莓恢复 12，口粮恢复 32，最高 100；满体力时不会消耗食物。
- NPC 买入价为卖出价的两倍，所有操作每次 1 件；界面显示实际价格。
- 行走每 3 秒保存，资产变化、到达、失焦和正常关闭时立即保存。异常强制退出最多损失最近约 3 秒的非资产旅行进度。
- 存档位置：macOS `~/Library/Application Support/WindtrailDemo/journey.json`；其他平台由 Godot `user://` 决定。
- `.bak` 保存上次有效快照。主文件损坏优先从备份恢复；两份均不可读时保留 `.damaged` 副本并显示新旅程提示。
- 本版为单进程单存档体验，不要同时运行两个正式实例；并发写存档与防篡改不在本 Demo 范围内。

## 工程结构

```text
project.godot             项目配置
main.tscn                入口场景
scripts/main.gd          输入、主循环、提示音与运行验证入口
scripts/state.gd         物品、配方、旅行、事务与存档
scripts/world.gd         程序化世界、角色、相机与资源点击
scripts/hud.gd           中文 HUD、背包、营地各窗口
scripts/slot.gd          拖动交换物品格
tests/test_state.gd      状态规则与异常路径测试
export_presets.cfg       macOS 导出配置
assets/fonts/            字体子集与 OFL 许可
THIRD_PARTY.md           素材来源和引擎许可说明
```

界面与 3D 相机都由代码构建，编辑器场景树在运行前只有入口节点。修改物品、配方、路线和任务时从 `state.gd` 常量入手；添加中文文本时同步更新字体子集。拖放使用 Godot [Control 的拖放接口](https://docs.godotengine.org/en/stable/classes/class_control.html#class-control-private-method-get-drag-data)。

## 检查与导出

从仓库根目录执行；将 `godot` 替换为实际 Godot 可执行文件路径。

```sh
godot --headless --path prototypes/trail-godot --editor --import --quit
godot --headless --path prototypes/trail-godot --script res://tests/test_state.gd
godot --path prototypes/trail-godot -- --smoke
godot --headless --path prototypes/trail-godot --export-release macOS "$PWD/outputs/trail-godot/Windtrail.app"
```

导出需要对应版本的 macOS 模板，项目已启用 universal 导出需要的 ETC2/ASTC 导入。

`--smoke` 使用 `smoke-only.json` 独立存档，自动运行旅行、采集、到达与制作，生成 `user://smoke-*.png` 后退出；它检验场景构建与渲染，不替代真实输入测试。`--qa` 从全新测试状态进入游戏，写 `qa-interactive.json`；`--qa-resume` 继续该测试存档。二者都不影响正式旅程。

自动化覆盖：采集重复/距离/容量、暂停、食物、耗尽与救援、配方扣料/成品容量、NPC 购买/出售、仓储守恒/失败回退、交换 UID、到达与任务幂等、升级、完整循环、存档重载/损坏恢复/写入失败。测试数据、截图和构建均不提交到 Git。
