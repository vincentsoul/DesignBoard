# 三层矿洞设施白模 V2

在原矿洞第三层白模基础上扩展为上、中、下三层。采用类似洋馆/警局的中枢回访、多翼房间、环形路线与门控节奏，但布局为原创；不是对既有游戏地图的复刻，也未声称达到其完整游戏内容规模。

## 文件与查看

- `mine-complex-three-storeys.blend`：完整可编辑白模。
- `exploded-overview.png`：三层并排分解轴测图，左为上层，中为原救援层，右为下层。
- `assembled-overview.png`：真实叠放结构。
- `vertical-exploded.png`：沿竖向分开的三层轴测图，展示原位对齐关系。
- `l2-plan.png`、`l3-plan.png`、`l4-plan.png`：分层俯视图。
- `layout.json`：房间坐标、门洞、楼梯与目标位置。

打开文件默认显示 `03_Vertical_Exploded` 场景。上下层在展示中分别移开42m，便于查看内部；`02_Exploded_Overview` 提供并排对照。这两个场景使用集合实例，仅用于展示，**真实模型的标高仍为+4、0、−4m**。切换到 `01_Assembled_Three_Storeys` 查看垂直对齐的三层，或使用 `Plan_L2`、`Plan_L3`、`Plan_L4` 单独查看。修改原始层集合会同步更新实例。

## 三层职责

|层|标高|功能与内容|
|---|---|---|
|L2 管理层|+4m|档案、宿舍、医务室、主管办公室、勘探实验室、保安室、西侧安全屋、东侧档案与展室、调度及通信；中庭上回廊作为导航中枢|
|L3 救援采矿层|0m|保留原入口、观察台、裂隙、旧脉通道、采矿区、救援区与塌方；增设中央回廊、东西楼梯、库房、维修间及安全屋|
|L4 动力层|−4m|取水、过滤、泵控、发电、配电、机修、蓄水与排水、锅炉、涡轮及电力控制；中庭底部可行走大厅|

中庭净开口16×4m，上、中层围绕开口设回廊和1.1m栏墙，下层有完整大厅。动力层合并部分房间为大跨度取水、机修、蓄水和锅炉区域，并设置设备体量占位，使其空间节奏与上层办公室不同。中庭与原观察台裂隙是两处不同空间。

## 竖向结构

西楼梯间平面范围 `(14,28,8,10)`，东楼梯间 `(58,22,8,12)`，三层严格对齐。每个相邻楼层使用一组U形实体阶梯：24级、每级高1/6m、踏步深0.3m、梯段净宽2m、中间平台深2m。上层楼板预留6×6m开口，避免楼板截断梯段。楼梯本身只建模，没有自动攀爬或传送逻辑。上层井口设1.1m护栏，仅在顶端梯段入口留口。

西侧维修梯为额外的维护接口；目前以封闭检修盖标注，不在强制路线连通性检查中作为可通行边。需要接入攀爬与开盖逻辑后再启用，防止直接绕过门控。

## 探索节奏

1. 从L2中央回廊开始探索管理层，档案室获得 `SERVICE_KEY`。
2. 解开西楼梯L2↔L3连接，进入采矿层；阿布初始已有离火斩，矿区G1可拆链；新增中央回廊也提供矿区的另一入口，因此V1的G1不再是全矿区的唯一门控。
3. 在L3矿区获得 `FUSE`，解开西楼梯L3↔L4连接。
4. 到L4电力控制室安装保险丝恢复 `POWER`。
5. 东楼梯两段与上锁的奖励房开放，形成更短的跨层回路；返回L3囚笼，用传音与离火斩救出小兽。
6. 获得 `EARTH` 后稳固原出口塌方，开启最终离开路线；维护梯可作为后续捷径设计；中层南侧安全屋与出口之间另设从安全屋一侧解开的门闩捷径（白模门块用 `unlock_from` 属性标注）。

目标顺序是拟实现的玩法规范，白模用独立门块及 `requires` 属性表达。只有实际接入状态与交互后，才能检验真实游戏流程。跨层门块位于对应楼梯顶部，可在Outliner按 `Gate_` 搜索；普通可通行门只建门楣，上电奖励房放有独立门块。

## 尺寸与墙体

仍使用米制，坐标 `(X,-Y,Z)`。主回廊4m，正常墙高3m，层间距4m，地板厚0.25m；普通门洞2m，楼梯宽2m。新房间坐标为墙体布置基准，居室之间的0.25m隔墙会占用房间边缘，不能当作所有房间的最终净尺寸；走廊相邻墙体向房间一侧偏移，保留走廊净宽。主通路与楼梯间分别检查。

V2新增环路会改变原单层版本的最短路线；这是扩建方案，不再要求所有玩家走完V1的整条旧脉迂回。旧文件保留，未覆盖。

## 检查与限制

最终门洞邻接图共44个空间节点（L2为19、L3为9、L4为16；原采矿层主体合并记为一个Core节点，因此不等于独立房间数），107处门洞和4段相邻楼层楼梯连接。

生成脚本检查物理门洞邻接图、按钥匙/供电顺序获取目标的可达性、初始不能下楼及未得保险丝不能进入动力层、解锁后全部区域可达、观察裂隙与中庭开口保留。生成报告在忽略目录 `outputs/mine-complex/`。

这类图检查不等同于角色胶囊测试。白模尚未实现角色控制、碰撞配置、机关脚本、AI、战斗、存档或完整镜头。两座楼梯的净空、栏杆、门块与角色通行，以及所有交互提示应在引擎中继续验收；尚未做首次游玩节奏测试。

重建：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python tools/blender/build_mine_complex.py
```

输入是保留的V1单层白模；重建将覆盖本目录内V2模型、预览与布局清单，手工编辑前请另存版本。

## 白模内的跨层关联标记

模型已增加可单独隐藏的 `CNX_` 标注集合，建筑几何保持原样：

- 橙色 `W`：西楼梯主线；L2↔L3需维修钥匙，L3↔L4需保险丝。
- 蓝色 `E`：东楼梯；两段均为恢复供电后开放的跨层捷径。
- 紫色虚线 `H`：封闭检修接口，未启用，不表示当前存在可通行捷径。
- 青色虚线：中庭上下层视觉联系，不是步行或攀爬通道。

每层楼梯井有同色轮廓和定位标杆，落脚区域标注去向与条件。默认竖向分解场景增加双向连接线、中文楼层标高和图例；真实叠放场景保留与实际标高对应的连接线。展示线只是导航标注，不是新增桥梁或碰撞体。

`CNX_Model_L2/L3/L4` 集合属于相应建筑层；`CNX_Vertical_Connections` 与 `CNX_Assembled_Connections` 是仅用于各自展示场景的关联线。隐藏这些集合即可查看纯白模。中文标注转换为字形网格，不依赖打开模型的机器安装中文字体；编辑文字可修改脚本后重建标记。相机朝向的说明文字是专用轴测展示标签，不应导出为关卡建筑。

预览：`connections-marked.png`。完整重建脚本已自动调用 `tools/blender/annotate_mine_connections.py`，不会在重建时丢失标记；也可在当前Blender文件内单独调用 `annotate_connections()` 更新，重复调用不会叠加旧标记。
